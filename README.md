# Localhost — Quick Start

A single-threaded, non-blocking (epoll-based) HTTP/1.1 server written
in Rust. This file gets you from zero to a running, demonstrable
server.

## 1. Build

```bash
cargo build
```

No external services or databases required. Only dependency beyond
the Rust toolchain is `python3` on PATH (used by the CGI demo route).

## 2. Run

```bash
cargo run -- config.toml
# or, after building:
./target/debug/localhost config.toml
```

The bundled `config.toml` starts one virtual server on two ports:

```
0.0.0.0:8080
0.0.0.0:8081
```

You should see:

```
listening on 0.0.0.0:8080
listening on 0.0.0.0:8081
```

Stop the server with `Ctrl+C`.

## 3. Routes in the bundled config

| Path        | Methods            | Behavior                              |
|-------------|---------------------|----------------------------------------|
| `/`         | GET                 | Static site from `./www`, index.html   |
| `/uploads`  | GET, POST, DELETE   | File storage in `./uploads`, listing on |
| `/old`      | GET                 | 302 redirect to `/`                    |
| `/cgi`      | GET, POST           | `.py` scripts in `./cgi` run via python3 |

Custom error pages for 400/403/404/405/413/500 live in `./www/errors`.

## 4. Demonstrate it's working

All commands below assume the server is running on port 8080 and are
run from the project root. `curl -i` is used so response headers are
visible.

### Static file serving

```bash
curl -i http://localhost:8080/
curl -i http://localhost:8080/css/style.css
curl -i http://localhost:8080/images/logo.png
```

Check: `200 OK`, correct `Content-Type` per file extension.

### 404 Not Found

```bash
curl -i http://localhost:8080/does-not-exist
```

Check: `404 Not Found`, custom error page body from `www/errors/404.html`.

### Redirect

```bash
curl -i http://localhost:8080/old
```

Check: `302 Found` with `Location: /`.

### Directory listing

```bash
curl -i http://localhost:8080/uploads
```

Check: `200 OK`, an HTML index of files in `./uploads`.

### Method not allowed

```bash
curl -i -X POST http://localhost:8080/
```

Check: `405 Method Not Allowed` (the `/` route only permits GET),
response includes an `Allow` header.

### File upload (POST) + retrieval (GET) + removal (DELETE)

Uploads are raw-body POSTs to the path you want the file stored at —
there is no multipart form parsing.

```bash
curl -i -X POST --data-binary "hello from curl" \
     http://localhost:8080/uploads/demo.txt

curl -i http://localhost:8080/uploads/demo.txt

curl -i -X DELETE http://localhost:8080/uploads/demo.txt

curl -i http://localhost:8080/uploads/demo.txt   # now 404
```

Check: `201 Created` on upload, file content echoed back on GET,
`204 No Content` on DELETE, `404` after deletion.

### Body size limit

```bash
head -c 20000000 /dev/zero > /tmp/big.bin
curl -i -X POST --data-binary @/tmp/big.bin http://localhost:8080/uploads/big.bin
```

Check: `413 Payload Too Large` (`client_max_body_size` in
`config.toml` is 10 MB).

### CGI (Python)

```bash
curl -i http://localhost:8080/cgi/hello.py
curl -i -X POST -d "message=hello+world" http://localhost:8080/cgi/hello.py
```

Check: `200 OK`, HTML body generated by `cgi/hello.py`, and the POST
response includes the posted message echoed back.

### Cookies and sessions

```bash
curl -i -c cookies.txt http://localhost:8080/session-info
curl -i -c cookies.txt -b cookies.txt http://localhost:8080/session-info
```

Check: first response sets `Set-Cookie: session_id=...`; the second
request (sending that cookie back) shows the same `session_id` with
`visit_count` incremented in the JSON body.

### Persistent connections / multiple requests per read

```bash
curl -i http://localhost:8080/ http://localhost:8080/css/style.css
```

Check: `curl -v` output shows `Re-using existing connection` for the
second request — one TCP connection served both.

### Malformed request survives

```bash
printf 'GARBAGE REQUEST\r\n\r\n' | nc localhost 8080
```

Check: `400 Bad Request` (not a hang or a silent close), and the
server keeps accepting new connections afterward.

Check: the server responds with `400 Bad Request` (not a crash or a
hang), and remains reachable for the next request afterward.

## 5. Browser walkthrough

Open `http://localhost:8080/` in a browser with DevTools open
(Network tab). Click through:

- Home → Uploads → Upload a file → CGI → Old link → 404 test
- Use the "Check my session" button on the home page
- Submit the message form on the CGI page

Inspect request/response headers (`Host`, `Cookie`, `Content-Length`,
`Set-Cookie`, `Location`, status codes) directly in DevTools.

## 6. Run the automated test suite

```bash
cargo test
```

124 tests across networking, HTTP parsing, routing, chunked bodies,
uploads, DELETE, sessions, CGI, timeouts/resource limits, and
filesystem/symlink security.

## 7. Configuration

Edit `config.toml` to add servers, ports, hostnames, routes, or CGI
mappings — see the existing entries as examples. Restart the server
after any change; configuration is loaded once at startup and
validated before the server binds any sockets. A malformed config
prints an error and exits without partially starting.
